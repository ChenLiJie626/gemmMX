MMA 映射速查

沐曦 C500 __builtin_mxc_mma_16x16x16i8，C = A(256×256) × Bᵀ。 这份是完整教程的提要， 只留讲「谁对应谁」的那几张图：从 lane 的两个号，一路映到大矩阵上的格子。 例子自始至终是同一条：block(0,1) / wave 1 / lane 17。

00

下标字典

全篇只有这几个号，先认准它们各自管什么：

记号取值管什么谁给的
p = lane % 160‥15A 的行 / B 的列 / C 的列硬件
q = lane / 160‥3交料时是 k 段，领货时是行组硬件
e0‥3累加器里第几个 int32 = 行组内第几行硬件
m, n0‥3wave 内 4×4 个 tile 的坐标我们摆的
c0‥3第几个 k 组（每组 64 个 k）我们摆的
w0‥3一次 16B 读里第几个 word我们摆的

一句话总纲：lane 是交数据的单位和存结果的单位， 但不是算一个数的单位 —— 算账的单位是 wave。 下面所有的「对不上」都是这句话的后果。

01

同一批 64 人，三张座位表

一条 MMA 要算 C[m][n] += Σ(k=0..15) A[m][k]·B[k][n]，16 个 k 得全齐； 可一条 lane 的寄存器只有 32 位 = 4 个 int8。 所以 k 必须切成 4 段分给 4 条 lane —— 一个输出格子的原料天生就散在好几条 lane 手里。

行 / k列
a 片段行 = lane%16k = 4·(lane/16) + 0‥3
b 片段k = 4·(lane/16) + 0‥3列 = lane%16
acc行 = (lane/16)·4 + e列 = lane%16

列对得上：b 的列和 acc 的列都是 lane%16 —— 一条 lane 交的那一列 B，正是它最后领走的那一列 C。 行对不上：a 的行是 lane%16，acc 的行却是 (lane/16)·4 + e。 B 那边自给自足，A 那边必须靠别人。

02

交进去的 ≠ 拿回来的

lane 17 在第一条 MMA(m=2, n=1, c=0, w=0) 里：
  交出去  a = A[161][16..19] = [ 2,  4, -1,  6]
          b = B[ 81][16..19] = [ 7,  2,  5,  2]
  这两段自己的点积 29 -> 落在 C[161][81]，归 lane 1

  它自己的 acc[2][1][0] 要的是 A[164] 那一行
    -> tile 内第 4 行 -> 由 lane%16 == 4 的那批交上来
    -> lane 4 / 20 / 36 / 52

03

一个输出格子，是谁凑的

反过来记一条通式：C[m][n] 落在 lane = 16·(m/4) + n，e = m%4（tile 内坐标）。

04

k 的顺序是乱的，但不重不漏。 k = 64c + 16q + 4w + j 是混合基数分解，0‥255 各覆盖一次； A 和 B 用同一套置换，配对不会错 —— 加法不在乎顺序。

05

片段 → 累加器：4+4 条读撑起 16 个 tile

次数字节
LDS 实际读32 条 × 16B512 B
MMA 逻辑消耗256 条 × (4+4) B2048 B
复用倍数—4×

固定一对 (m,n)，c、w 两重循环的 16 条 MMA 全打在同一个 acc[m][n] 上，各带 16 个 k， 16×16 = 256 正好一个 K 窗口。累加全程在寄存器里，不落 LDS、不落显存。

06

归位：四段偏移首尾相接

没有「搬回去」这一步。每条 lane 自己算出全局地址直接 store。

层行偏移列偏移谁决定
blockblockIdx.y * 128blockIdx.x * 128启动配置
wavewave_m * 64wave_n * 64tid / 64 拆 2×2
tilemm * 16nn * 16两重循环
lane(lane/16)*4 + elane % 16硬件定死
 
// 正向
row = block_row + wave_m*64 + mm*16 + (lane/16)*4;
col = block_col + wave_n*64 + nn*16 + (lane%16);
C[(row + e)*N + col] = acc[mm][nn][e];

// 反查：给定 C[m][n]，谁写的
by = m/128;            bx = n/128;
wave_m = (m%128)/64;   wave_n = (n%128)/64;
mm = (m%64)/16;        nn = (n%64)/16;
lane = ((m%16)/4)*16 + (n%16);    e = m%4;

坑一：dim3 grid(N/128, M/128) —— x 管列、y 管行， block_row 取的是 blockIdx.y。写反了不报错，方阵时尤其阴险。
坑二：教学 kernel 不做边界判断，M/N 须 128 整除、K 须 256 整除。

07

一条 lane 写 64 次，落在哪 64 格

lane 17 碰到的列永远是 65 / 81 / 97 / 113，全都 ≡ 1 (mod 16) —— 因为列号里除了 lane%16，其余都是 16 的倍数， 一条 lane 一辈子只写固定那 4 列。

粒度次数每次合计
一个 acc44 B16 B
一条 lane644 B256 B
一个 wave64 条指令64 lane × 4 B16 KB

一条 store 指令里，每 16 条 lane 的列号连号凑成 64 字节一段， 一条指令产生四段 —— 合并发生在 lane 之间，不在 lane 内部。

08

整条链，一个例子走到底

C[164][81]
  block (bx=0, by=1)     管 m 128-255, n 0-127
  wave 1                 wave_m=0, wave_n=1   -> m +0,  n +64
  tile  (mm=2, nn=1)                          -> m +32, n +16
  lane  17 的 acc[2][1][0]                    (block 内 tid = 81)

  行 = 128 + 0 + 32 + (17/16)*4 + 0 = 164
  列 =   0 + 64 + 16 + (17%16)     =  81

  它读的   A[129/145/161/177] 这四行的四段 k
  它持有的 C[164..167][81]
  供它 A[164] 的是 lane 4 / 20 / 36 / 52
  —— 读的、算的、持有的，是三组不同的坐标
